# Редактор фигур

Лабораторная работа на C++ и Qt. В программе можно добавлять прямоугольники,
эллипсы и многоугольники, перемещать их мышью и соединять линиями.
Фигуры и связи сохраняются в SQLite, поэтому после перезапуска сцена
восстанавливается.

## Как пользоваться

Слева выбираются тип и размеры новой фигуры. Для многоугольника также
задаётся число вершин. Чтобы соединить две фигуры, нужно выделить их
с зажатым Ctrl (Command на macOS) и нажать «Соединить две фигуры».
Можно выделять несколько объектов рамкой.

Внизу находится таблица с ID, типом, связями и количеством фигур каждого
типа. Фильтры меняют только таблицу и не удаляют данные. Кнопка удаления
удаляет выбранные фигуры вместе с их связями.

Значки в столбце количества соответствуют условию задания: один при 1–3
фигурах, два при 4–10 и три при количестве больше 10. Учитывается общее
число фигур данного типа в базе, даже если часть строк скрыта фильтром.

## Где находится код

- `src/main.cpp` — запуск приложения.
- `src/mainwindow.*` — окно, кнопки и обработчики действий.
- `src/database.*` — работа с SQLite.
- `src/shapeitem.*` — фигуры и линии на сцене.
- `src/shapemodel.*` — модель таблицы и отрисовка значков.
- `tests/editor_tests.cpp` — тесты.

Подробнее о работе классов написано в [CODE_EXPLANATION.txt](CODE_EXPLANATION.txt).

## Сборка

Нужны компилятор C++17, CMake 3.21 или новее и Qt 6.5 или новее
с модулями Widgets, SQL и драйвером QSQLITE. Для тестов нужен Qt Test.

Из папки проекта:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="<путь к Qt>"
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
```

Вместо `<путь к Qt>` нужно указать каталог установленного комплекта Qt.
Если CMake уже находит Qt, этот параметр не нужен. На Windows с MinGW
к первой команде нужно добавить `-G "MinGW Makefiles"`, а каталоги `bin`
Qt и компилятора должны быть в PATH. Компилятор должен подходить
к установленной сборке Qt.

Сборка без тестов: добавить к первой команде `-DBUILD_TESTING=OFF`.
В этом случае команду `ctest` выполнять не нужно.

## Запуск и разные ОС

После сборки исполняемый файл находится в `build`:

- Windows с MinGW — `build/QtShapeEditor.exe`;
- Windows с Visual Studio — обычно `build/Release/QtShapeEditor.exe`;
- Linux — `./build/QtShapeEditor`;
- macOS — `open build/QtShapeEditor.app`.

На каждой ОС проект нужно собирать отдельно. При запуске должны быть
доступны библиотеки Qt. Шрифты, вид элементов и расположение файла базы
могут отличаться. Путь базы выбирается через `QStandardPaths::AppDataLocation`.
Свою базу можно указать параметром `--db "путь/к/файлу.sqlite"`.

Проверено на Windows 11 с Qt 6.8.3 и MinGW-w64 13.1. Семь тестовых
сценариев прошли. На Linux и macOS сборка отдельно не проверялась.

Из ограничений: нет отмены действий, изменения размеров после создания
и отдельной кнопки удаления линии. После добавления или удаления объектов
сцена строится заново, поэтому программа рассчитана на небольшие схемы.
